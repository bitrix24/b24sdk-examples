# Шаблон плана

Использовать этот шаблон для файлов в `.tasks/`. Подставлять только релевантные разделы; пустые блоки удалять.

```md
# План: <краткое название задачи>

## Summary

Кратко описать цель и ожидаемый результат.

## Context

- Зафиксировать, какие файлы, подсистемы и ограничения проекта влияют на задачу.
- Указать только те артефакты, которые реально были прочитаны.

## Implementation Changes

- Перечислить конкретные изменения по файлам или подсистемам.
- Для каждого изменения указать ожидаемый результат, а не общую формулировку.

## Risks and Assumptions

- Явно перечислить допущения.
- Отдельно перечислить риски, которые могут потребовать возврата к плану.

## Test Plan

- Указать обязательный `make test`.
- Добавить дополнительные проверки через `make`, если они релевантны задаче.
- Описать ручную проверку только там, где её нельзя заменить автоматикой.

## Review Checklist

- [ ] План сохранён в `.tasks/`
- [ ] Шаги однозначны для исполнителя
- [ ] План не противоречит текущей архитектуре проекта
- [ ] План не содержит явных лакун по конфигу, тестам, миграциям, документации и зависимостям
- [ ] Связанные чеклисты обновлены или явно отмечено, что их нет в текущем дереве

## Review Notes

### Однозначность

- Зафиксировать найденные неоднозначности и то, как они устранены.

### Архитектурная проверка

- Зафиксировать, с чем именно сверялся план.

### Лакуны

- Зафиксировать недостающие куски или отметить, что явных лакун не найдено.
```
