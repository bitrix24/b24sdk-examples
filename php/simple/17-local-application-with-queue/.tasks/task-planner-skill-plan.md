# План: создать project-local skill `task-planner`

## Summary

Добавить в репозиторий project-local skill, который сначала запрашивает формулировку задачи, затем строит план работ, сохраняет его в `.tasks/` и после сохранения перепроверяет план на однозначность для исполнителя, соответствие архитектуре проекта и наличие лакун.

## Context

- Источник проектных ограничений: `AGENTS.md`.
- Операционные команды должны запускаться через `make`, поэтому для инициализации и валидации skill нужны make-targets.
- В репозитории уже используется папка `.tasks/`, в ней есть план-пример `pass-handler-url-from-config-plan.md`.
- В проекте нет отдельной локальной папки со skills, значит нужно добавить versioned project-local каталог.

## Implementation Changes

- Добавить в `Makefile` target `skill-init-task-planner`, который создаёт каркас skill в `.codex/skills/task-planner`.
- Добавить в `Makefile` target `skill-validate`, который валидирует произвольный skill по пути `SKILL_PATH=...`.
- Инициализировать skill `task-planner` как project-local resource через make-target.
- Заполнить `.codex/skills/task-planner/SKILL.md` конкретным workflow планирования и последующей проверки сохранённого плана.
- Добавить reference-файлы с шаблоном плана и рубрикой проверки, чтобы другой исполнитель использовал единый формат.
- Сохранить отдельный план этой задачи в `.tasks/task-planner-skill-plan.md` и зафиксировать результат его проверки.

## Risks and Assumptions

- Предполагается, что project-local расположение `.codex/skills/` приемлемо для команды и удобнее, чем пользовательский `$HOME/.codex/skills`.
- Предполагается, что для этого skill достаточно инструкций и reference-файлов без дополнительных исполняемых скриптов.
- Отдельного checklist-файла по этой задаче в текущем дереве нет, поэтому статус будет отражён в `Review Checklist` этого плана.

## Test Plan

- Проверить структуру skill через `make skill-validate SKILL_PATH=.codex/skills/task-planner`.
- Если системный валидатор недоступен из-за отсутствия Python-зависимостей, добавить project-local эквивалент и использовать его через тот же make-target.
- Запустить обязательный `make test`.
